# 架构设计

## 整体架构

系统分为三层：边缘缓存层、持久缓存层、管理应用层。

```
┌─────────────────────────────────────────────────────────────┐
│                         用户浏览器                            │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                    Cloudflare DNS + CDN                       │
│  - 国内访问优化                                                │
│  - cdn.yourdomain.com 指向 Workers                             │
│  - admin.yourdomain.com 指向 Vercel                            │
└───────────────────────────┬─────────────────────────────────┘
                            │
            ┌───────────────┴───────────────┐
            │                               │
            ▼                               ▼
┌───────────────────────┐       ┌───────────────────────┐
│   cdn.yourdomain.com  │       │  admin.yourdomain.com │
│   Cloudflare Workers  │       │  Vercel + Nuxt 3      │
│   + R2 持久缓存        │       │  管理后台             │
└───────┬───────────────┘       └───────┬───────────────┘
        │                               │
        │ 回源 / 写入                    │ 读写配置、统计
        ▼                               ▼
┌───────────────────────┐       ┌───────────────────────┐
│     源站服务器         │       │   Cloudflare D1       │
│  your-origin-server.com│       │   元数据、配置、统计    │
└───────────────────────┘       └───────────────────────┘
```

## 缓存策略

采用三层缓存架构：

1. **Cloudflare CDN 边缘缓存**
   - 命中时直接从边缘节点返回
   - 无限带宽，响应最快
   - 通过 `Cache-Control` 控制缓存时间

2. **R2 持久缓存**
   - 未命中 CDN 时检查 R2
   - 适合长期存储热门资源
   - 零出向流量费用

3. **源站回源**
   - R2 也未命中时回源拉取
   - 写入 R2 和 CDN 缓存
   - 异步写入，不阻塞响应

## 组件职责

| 组件 | 职责 |
|---|---|
| Cloudflare Workers | 接收请求、缓存控制、回源逻辑、管理接口 |
| Cloudflare R2 | 持久化缓存资源文件 |
| Cloudflare D1 | 存储源站配置、缓存统计信息 |
| Vercel + Nuxt 3 | 管理后台前端、展示页面 |
| Cloudflare DNS | 域名解析、国内访问路由 |
| Supabase（未来可选） | 用户系统、OAuth、审计日志 |

## 数据流

### 资源请求流程

```
用户请求 cdn.yourdomain.com/images/abc.jpg
        │
        ▼
[1] Cloudflare CDN 缓存命中？
        │ 是 → 直接返回资源
        │ 否
        ▼
[2] R2 缓存命中？
        │ 是 → 返回资源，异步写入 CDN
        │ 否
        ▼
[3] 回源源站
        │
        ▼
[4] 写入 R2，异步写入 CDN
        │
        ▼
[5] 返回给用户
```

### 管理操作流程

```
管理员打开 admin.yourdomain.com
        │
        ▼
Nuxt 3 渲染管理界面
        │
        ▼
直接调用 Workers 管理接口（CORS + Bearer Token）
        │
        ▼
写入 D1 或刷新缓存
        │
        ▼
更新源站配置 / 刷新缓存 / 查看统计
```

## 扩展性

### 多源站路由

通过配置表支持不同路径前缀路由到不同源站：

| 路径前缀 | 源站 |
|---|---|
| `/a/*` | `https://origin-a.com` |
| `/b/*` | `https://origin-b.com` |
| `/*` | `https://default-origin.com` |

### 缓存预热

对热点资源主动发起请求，提前写入 R2 和 CDN：

```
预热脚本 → 读取热点列表 → 请求 cdn.yourdomain.com/xxx → 触发缓存写入
```

### 防盗链

可选策略：

- Referer 白名单
- Token 签名验证
- 时间戳防重放
